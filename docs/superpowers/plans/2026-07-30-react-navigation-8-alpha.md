# React Navigation 8 Alpha Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade Surely to React Navigation 8.0.0 alpha on a branch so the navigation chrome can use `UNSTABLE_CornerInset` to clear the iPadOS windowed-mode traffic light buttons.

**Architecture:** Bump all three React Navigation packages to pinned alpha versions plus `react-native-gesture-handler@3` (required by drawer v8), rebuild native since `@react-navigation/native@8` now ships an iOS podspec, then add `UNSTABLE_CornerInset` in two places — the custom header for small screens and the custom drawer content for all screens. Verification on an iPadOS 26 simulator is the decision gate; test-suite repair is deliberately sequenced after it.

**Tech Stack:** Expo SDK 57, React Native 0.86, React 19.2.3, React Navigation 8 alpha, react-native-gesture-handler 3, react-native-paper 5, Jest + jest-expo, Cypress.

**Spec:** `docs/superpowers/specs/2026-07-30-react-navigation-8-alpha-design.md`

**Branch:** `react-navigation-8-alpha` (already created; the spec commit 33bfe0d is its tip).

---

## A Note On Method

This is a dependency upgrade and native-integration spike, not a feature build. The
standard red-green-refactor cycle does not structure most of it: you cannot write a
failing unit test for "pod install resolves the ReactNavigation pod" or for a native
iPadOS view that renders `null` off-iOS. The plan substitutes **explicit verification
gates** — each task states the exact command and the exact expected output, and you do
not proceed past a gate that fails.

Tasks 8 and 9 repair the existing test suites. That ordering is intentional and was
chosen by the project owner: do not spend effort on the JS test environment before
knowing the feature works on a real iPad.

## Task 6: Add the corner insets

The export is `UNSTABLE_CornerInset`, uppercase. The documentation page's URL anchor
lowercases it (`#unstable_cornerinset-component-...`) but the actual export from
`@react-navigation/native` is `UNSTABLE_CornerInset`. It renders `null` on non-iOS
platforms, so web and Android are unaffected at runtime.

Props: `direction` is `'horizontal' | 'vertical'`, `edge` is `'left' | 'right' | 'top' | 'bottom'`.
The component reserves the width (horizontal) or height (vertical) of the traffic light
area at the given edge.

**Files:**
- Modify: `src/components/NavigationBar.js`
- Modify: `src/components/NavigationDrawer.js`

- [ ] **Step 1: Add the header inset import**

In `src/components/NavigationBar.js`, add as the first import line — package imports sort
before relative ones, and `@` sorts before `r`:

```js
import {UNSTABLE_CornerInset} from '@react-navigation/native';
```

The import block becomes:

```js
import {UNSTABLE_CornerInset} from '@react-navigation/native';
import {useColorScheme} from 'react-native';
import {Appbar} from 'react-native-paper';
import {large, useBreakpoint} from '../breakpoints';
import {SURELY_GREEN} from '../useTheme';
```

- [ ] **Step 2: Render the header inset**

Still in `src/components/NavigationBar.js`, replace the returned JSX:

```jsx
    <Appbar.Header style={headerStyle}>
      {back ? (
```

with:

```jsx
    <Appbar.Header style={headerStyle}>
      {showDrawerToggle && (
        <UNSTABLE_CornerInset direction="horizontal" edge="left" />
      )}
      {back ? (
```

It must be the first child so it pushes the back and menu buttons clear of the traffic
lights. The `showDrawerToggle` gate — already defined in this file as
`breakpoint !== large` — is deliberate: on large screens the permanent drawer sits to the
left of the header, so the header does not touch the window's left edge and must not be
inset.

- [ ] **Step 3: Add the drawer inset import**

In `src/components/NavigationDrawer.js`, the first import line is already
`import {useLinkTo} from '@react-navigation/native';`. Extend it — uppercase sorts first
within the braces:

```js
import {UNSTABLE_CornerInset, useLinkTo} from '@react-navigation/native';
```

- [ ] **Step 4: Render the drawer inset**

Still in `src/components/NavigationDrawer.js`, replace:

```jsx
    <DrawerContentScrollView style={scrollViewStyle} {...navProps}>
      {state.routes.map((route, index) => (
```

with:

```jsx
    <DrawerContentScrollView style={scrollViewStyle} {...navProps}>
      <UNSTABLE_CornerInset direction="vertical" edge="top" />
      {state.routes.map((route, index) => (
```

Unconditional, unlike the header: the drawer occupies the window's top-left whenever it
is visible, in both `permanent` and `back` modes.

If you applied the slice from Task 5 Step 2, keep it — the line reads
`{state.routes.slice(0, state.index + 1).map((route, index) => (`.

Run:

```bash

```

Expected: both pass. If `format:check` fails, run `yarn format` and re-check.

- [ ] **Step 6: Confirm nothing regressed on iPhone**

Run `yarn ios` (or reload the running app). Confirm the header still renders correctly
and the drawer items are not visibly shifted on a non-windowed device — the inset should
measure zero when there are no traffic lights.
